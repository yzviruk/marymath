# MaryMath — тренажер з математики для Марії (7 років, 2 клас)

Гейміфікована PWA для Android-планшета (горизонтально, 1280×800) за сингапурською методикою (CPA: предмети → малюнок → запис).
Мова інтерфейсу — українська. Ділення пишемо знаком «:».

## Джерела правди
- План (Claude Docs): https://claude.ai/artifact/UkTVKSt1BjxTzymsXenKzz — читати docs-інструментами, не web-fetch.
- Макети (Claude Design canvas): https://claude.ai/artifact/A3YQXGDtv9BfLAL4pHUXmR
  Локальна копія: `design/project/*.dc.html` (+ `canvas.json`). Перед зміною макета — `read` актуальної версії з артефакту
  (користувач редагує полотно вручну), потім публікувати з `root` = `design` через Artifact tool.
- Робочі аркуші дитини (приклади ×/:): `docs/worksheets/`.

## Погоджені рішення
- Додавання/віднімання в стовпчик до 1000; множення/ділення як на аркушах: множники 2–7 і 10, добуток до 35 (спершу до 20), без остачі.
- Логіка завдань — `app/src/engine/` (генератори рівнів, перевірка, `classifyError`, `buildLevel`, `similarTask`). Острів «Задачі» (?1, ?2) — на етапі 5. :3 приймає обидва прочитання малюнка, ціле — першим.
- Числова шкала 0–20 одним рядком, завжди вгорі екранів із завданнями; стрибки-дуги для ×, : і переходу через 10.
- Типова помилка дитини: пише ділення навпаки (4 : 6 = 24) — окремий рівень :3 і пояснення через bar model «спочатку — скільки всього».
- Кілька профілів дітей на пристрої, індивідуальна статистика, панель батьків за PIN; дані в IndexedDB + експорт/імпорт JSON.
- Улюбленці: мальтіпу, котик, єдиноріг, панда, капібара (власні SVG, компонент `Pet`). Ім'я за замовчуванням «Персик».
- Острови: Додавання (ліс), Віднімання (пустеля), Множення (цукерки), Ділення (кристали), Задачі (замок).
  Рівні позначаються знаком дії + номер: +1…+7, −1…−5, ×1…×6, :1…:5; бос — корона ♛.
  Відкриття (21.11.2026): на всіх 4 островах дій з початку відкритий перший рівень; наступний — після 7+ правильних у попередньому;
  «Задачі» — після всіх 4 босів. Зроблено в 5а (21.11.2026). E2E відкривають рівні через `e2e/unlock.ts` (зірки попереднім рівням прямо в IndexedDB).
- Без таймерів у основних рівнях; пояснення помилки в 3 кроки (підказка → покрокове пояснення → схожий приклад).
- Стовпчик: відповідь перевіряється лише після «Перевірити» (улюбленець по ходу називає розряд і числа, не правильність); перенесення дитина ставить сама — торканням кружечка над розрядом з'являється «1», повторне торкання прибирає (не поставила, але відповідь правильна — лише нагадування); кружечки обмінюються перетягуванням лише в додаванні (C на перших 3 прикладах з перенесенням, далі P, на босах A); багато кружечків зменшуються (`diskSize`).
  Віднімання (21.11.2026): над кожним розрядом кружечок позичання — дитина торкається й вписує, що стало (0–19; «1» чекає другої цифри), цифра під ним закреслюється; не перевіряється по ходу, лише нагадування. Панелі кружечків розрядів у відніманні під час розв'язування немає — тільки в поясненні помилки (`borrowMarksAt` вписує числа по кроках).
- Стиль: Nunito; тло #EAF3FF; акцент #5B3FD6; сотні #2F6FED, десятки #138A55, одиниці #E8770E; успіх #1E9E63; мультяшно.
- Стек: Vite + TypeScript + React, vite-plugin-pwa, IndexedDB, Vitest, Playwright; деплой GitHub Actions → GitHub Pages.

## Робочі правила
- Спочатку погодження з користувачем, потім імплементація. Кожен етап: короткий план → «погоджую» → код → тести → push → оновити план (чекліст у кінці розділу «Дизайн у Claude Design»), CLAUDE.md і пам'ять.
- Поле відповіді: перша цифра після невдалої перевірки замінює старе значення (у стовпчику — вміст клітинки під курсором).
- Публікація артефактів іноді блокується класифікатором дозволів — повторити або попросити користувача підтвердити.
  Публікація в полотно: спершу `read` артефакту (без `path`), інакше відмова «haven't viewed the latest version».
- Windows: імена файлів не чутливі до регістру — не створювати `foo.ts` поруч із `Foo.tsx`. Файли з лапками/апострофами писати Write, не bash-heredoc.
- Перевірка вигляду: `npm run build && npm run preview` (порт 4173) + скриншоти Playwright у scratchpad; після — зупинити сервер.
  Playwright перевикористовує сервер на 4173 (`reuseExistingServer`) — якщо там висить старий preview, e2e тестують старий збір; спершу зупинити його.

- `column/` — екран стовпчика: `columnInput.ts` (стан введення), `texts.ts` (репліки й кроки пояснення), `disks.ts` + `DiskPanel.tsx` (кружечки, drag), `ColumnBoard.tsx`, `ColumnTask.tsx` (3 кроки помилки).
- `facts/` — екран × і :: `FactTask.tsx` (етапи C/P/A, помилка в 3 кроки, `ExplainPanel` — кроки 1–2 на всю ширину, крок 3 — знову екран завдання), `Pictures.tsx` (коробки, масив з поворотом, кошики з перетягуванням, групи торканням, `BarModel`, `Triangle`, `WideLine` 0–35), `Equation.tsx` (віконця), `factInput.ts` (введення, :3 — торкання чисел), `objects.ts` (кошики, групи), `texts.ts` (умови, підказки, `explanation`), `words.ts` (відмінки після числа).
- `screens/` — `WhoPlays`, `MapScreen` (карта за макетом: море 880×644, 4 острови зі стежками й вузлами рівнів — пройдені із зірками, поточний фіолетовий з улюбленцем (`petSpot`), закриті із замком і реплікою «відкриється, коли пройдеш …»; табличка «пройдено / усього»; замок «Задачі»; праворуч «Продовжити» + улюбленець; графіка островів — `mapArt.ts`, згенерована з `Map.dc.html`), `LevelRun` (10 завдань, монетки 3/1/1, бонус 5, зірки 7/9/10, повтор учорашніх помилок через `LevelDef.rebuild`; `ColumnTask` або `FactTask`; режими × і : — `factModes`), `LevelDone` (+ «Нова рідкісна річ!»), `PetHome` (кімната з речами за `SPOT`, перейменування улюбленця, магазин: вкладки Одяг/Іграшки/Кімната, купівля в два торкання «Купити за N? ## Етап 4 — рішення (21.11.2026)
- Режими × і : (`LevelRun.factModes`): перші 3 завдання рівня — предмети (C); ×1, ×2, :1, :2, :3 далі з малюнком (P); ×3…×6 далі лише запис; :4 — завжди трикутник; :5 і боси — лише запис (A). Малюнок з'являється за «Підказкою», коли стрибки не вміщаються на 0–20.
- :1 — яблука перетягуються з купки в кошики (і назад); :2 — камінці торкаються по одному, `size` штук стають групою, торкання групи її розбирає; :3 — числа торкаються у віконця, торкання віконця повертає число.
- Помилка: 1-ша — підказка за типом (`firstHint`), віконця хитаються, перша цифра замінює; 2-га — пояснення: «Що на малюнку?» → правило + bar model / стрибки (понад 20 — `WideLine` 0–35) → «Запишу сам» (дитина вписує правильно, неправильна цифра — «Ще раз!») → схожий приклад.
- Для проби відкриті всі рівні × і :; правила відкриття островів — на етапі 5.
